## Task 1: Input requests + the event model

**Files:** `crates/gvm/src/glk.rs`, `exec.rs`, `asm.rs`, `GLULX_NOTES.md`.

`glk_request_line_event`(`_uni`) records, on a window, a pending **line** request (buffer addr, maxlen, initlen); `glk_request_char_event`(`_uni`) a pending **char** request; `glk_cancel_line_event`/`cancel_char_event` clear them (cancel fills a partial event). The Glk **event struct** is 4 words `(type, win, val1, val2)`: line event → `(evtype_LineInput=3, win, length, 0)`; char → `(evtype_CharInput=2, win, keycode, 0)`.

- [ ] **Step 1:** Note the event/input model + keycodes in `GLULX_NOTES.md` (Glk spec §"Events"/"Character Input").
- [ ] **Step 2: Failing tests:** `request_line_event` sets pending state on the window; a request on an already-requested window is a diagnostic; `cancel_line_event` clears it and reports the partial; char requests likewise; an internal `deliver_line(win, bytes)` writes the bytes into the request buffer (truncated to maxlen, Latin-1/Unicode per the request) and produces the right event tuple.
- [ ] **Step 3: Implement** the pending-request state + `deliver_line`/`deliver_char` helpers (used by `glk_select` in Task 2).
- [ ] **Step 4: Commit** — `feat(gvm): Glk line/char input requests + event model`.

## Task 2: `glk_select` suspend/resume + input `StepResult`

**Files:** `crates/gvm/src/exec.rs`, `asm.rs`.

`glk_select(event_addr)` suspends the VM until an event is delivered; `glk_select_poll` returns immediately (only non-blocking events — for 3a-2, returns `evtype_None` unless a timer/arrange is pending). Add:

```rust
pub enum StepResult {
    Continue,
    Quit,
    /// glk_select is waiting for input on `window` (Line or Char). The host
    /// supplies the event via supply_line/supply_char, then resumes.
    NeedInput { window: u32, kind: InputKind /* Line { maxlen } | Char */ },
}
```

- [ ] **Step 1: Failing tests:** a program that `request_line_event` then `glk_select` → `step()` yields `StepResult::NeedInput{ Line }`; `Machine::supply_line(bytes)` writes the line + stores the event struct at `event_addr` + resumes (next `step` is `Continue`); same for `supply_char`/`NeedInput{ Char }`; `glk_select` with no pending request is a diagnostic (or blocks → treat as no-input/Quit-safe). The event struct is written correctly.
- [ ] **Step 2: Implement** `glk_select` (record the `event_addr`; suspend via `NeedInput`), `supply_line`/`supply_char` (deliver via Task 1 helpers, write the event struct, clear the pending request, resume), and `glk_select_poll`.
- [ ] **Step 3: Commit** — `feat(gvm): glk_select suspend/resume via StepResult::NeedInput`.
