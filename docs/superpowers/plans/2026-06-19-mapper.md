# mapper — Automapper Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A VM-agnostic automapper that turns a stream of (location, direction) observations into a directed map graph, lays rooms out on a grid (Auto/Manual modes), routes orthogonal connectors, and serializes the result — all driven by synthetic events, with no dependency on the VM or the UI.

**Architecture:** A new `mapper` library crate, layered: `direction` → `graph` (rooms + directed edges + observe) → `layout` (grid placement, Auto/Manual) → `router` (orthogonal connectors) → `render` (abstract grid-coordinate render model the TUI/exporter consume) → `persist` (serde_json serialize/deserialize). The mapper takes plain inputs (`RoomId = u16`, name `String`, parsed `Direction`); the future `app` milestone bridges the VM's `current_location` to `Mapper::observe`. Nothing here depends on `zvm`.

**Tech Stack:** Rust (stable, edition 2021), the existing Cargo workspace. The `mapper` crate MAY use `serde` + `serde_json` (verified reachable on crates.io) for persistence — this is the only external-dependency exception and is confined to `persist.rs` types via derives.

## Global Constraints

- **VM-agnostic:** `mapper` must NOT depend on the `zvm` crate. Inputs are plain values (`RoomId = u16`, `String`, `Direction`). All tests use synthetic event streams, no VM. (spec §2 mapper boundary, §8)
- **Room identity = `RoomId` (a `u16`, the Z-machine object number).** Same name + different id ⇒ distinct rooms; same id ⇒ the same room even if the name string differs. NEVER key rooms by name. (spec §3)
- **Connections are directed edges keyed by `(origin RoomId, Direction)` → dest RoomId. No symmetry assumed anywhere.** (spec §3)
- **Direction set:** `n/s/e/w/ne/nw/se/sw/u/d/in/out` plus `Unknown` for non-compass/teleport moves. Compass + long forms recognized; a room change after a non-direction command still adds the room joined by an `Unknown` edge. **Rooms are never lost.** (spec §4)
- **Rooms never overlap** on the grid. (spec §3)
- **Layout is a per-map mode:** `Auto` (default) or `Manual`. Auto owns positions (greedy incremental, minimal movement). Manual freezes positions; the player nudges. Switching Auto→Manual seeds positions from the current Auto layout. (spec §3 Layout modes)
- **Connectors are routed orthogonal paths:** direction is carried by which side of the origin room the connector departs; the path bends through gutters to reach the dest. `Distorted` is the last-resort fallback when the departure-side direction can't be honored. (spec §3 Connections, "When a clean layout is impossible")
- **Light correction operations only (v1):** rename room (label override), nudge (Manual), delete a connection, relabel an `Unknown` edge, edit notes. No room-adding/freehand drawing. (spec §5)
- **Persisted data:** layout mode, rooms (id, label override, notes, position), connections (origin, dir, dest, distorted flag, relabeled dir). View state (zoom/scroll) is NOT persisted (it's the TUI's, milestone 3). (spec §5)
- **No file I/O in `mapper`:** persistence serializes to/from a `String`; the `app` milestone writes files keyed by IFID. (spec §5)
- **TDD:** failing test first, run to see fail, implement, see pass. Commit per green task. Run `cargo test -p mapper` (cargo is on PATH).

### Task 4: Auto layout — greedy incremental placement + collision avoidance

**Files:**
- Create: `crates/mapper/src/layout.rs`
- Modify: `lib.rs` (`pub mod layout;`), `mapper.rs` (call layout after observe)
- Test: inline in `layout.rs`

**Interfaces:**
- Consumes: `MapGraph`, `Direction`, `grid_offset`.
- Produces:
  - `pub enum LayoutMode { Auto, Manual }` (derive `Debug, Clone, Copy, PartialEq, Eq`; `Default` = `Auto`).
  - `pub fn relayout_auto(graph: &mut MapGraph)` — assigns `Room.pos` for all rooms in Auto mode using greedy incremental placement with **minimal movement**:
    - Rooms already having a `pos` keep it (minimal movement) unless a hard overlap forces a move (it shouldn't, since we only place new rooms into free cells).
    - For a room with no `pos`: find an edge `(origin, dir, room)` where `origin` has a `pos` and `grid_offset(dir)` is `Some(delta)`. Desired cell = `pos(origin) + delta`. If free, place there. If occupied, spiral-search outward from desired for the nearest free cell and place there, and set that connection's `distorted = true` (it couldn't sit exactly at the offset).
    - For a room reachable only via `Up/Down/In/Out/Unknown` edges (no `grid_offset`): place it at the nearest free cell to its origin (spiral from origin), connection stays non-distorted (it's a stub, handled by the router/render, not a grid offset).
    - The very first room (no incoming placed edge) goes at `(0,0)`.
    - Process rooms in a deterministic order (e.g., BFS from `current` or by ascending id) so layout is reproducible. Iterate until all rooms have a `pos`.
  - `pub fn occupied_cells(graph: &MapGraph) -> BTreeSet<(i32,i32)>` — helper.
  - `pub fn nearest_free_cell(occupied: &BTreeSet<(i32,i32)>, from: (i32,i32)) -> (i32,i32)` — spiral search (the `from` cell itself if free).

### Task 7: Orthogonal edge router

**Files:**
- Create: `crates/mapper/src/router.rs`
- Modify: `lib.rs` (`pub mod router;`)
- Test: inline in `router.rs`

**Interfaces:**
- Consumes: `MapGraph`, `Connection`, `Direction`, `grid_offset`, `opposite`.
- Produces:
  - `pub enum Side { Top, Bottom, Left, Right }` and `pub fn side_for(dir: Direction) -> Option<Side>` (N→Top, S→Bottom, E→Right, W→Left; diagonals → pick the dominant axis, e.g. NE→Top, SE→Bottom, NW→Top, SW→Bottom — document the choice; Up/Down/In/Out/Unknown → None, rendered as a stub).
  - `pub struct RoutedEdge { pub origin: RoomId, pub dest: RoomId, pub dir: Direction, pub points: Vec<(i32,i32)>, pub distorted: bool, pub is_stub: bool, pub label: Option<String> }` — `points` is a polyline in a FINE routing grid where each room cell at logical `(c,r)` maps to fine cell `(2c, 2r)` and gutters are the odd fine cells. The polyline starts at the origin's departure-side midpoint (fine coords) and ends at the dest's arrival side; bends are orthogonal.
  - `pub fn route_all(graph: &MapGraph) -> Vec<RoutedEdge>` — for each connection:
    - compute `side_for(dir)`; if `None` ⇒ `is_stub = true`, `points` = a short 1-segment stub off the origin, `label = Some(short dir name)` (e.g. "U","D","IN","OUT","?").
    - else compute departure point (origin side midpoint in fine grid) and arrival point (dest's `opposite(side)` midpoint). Build an orthogonal path with ≤2 bends (L or Z) between them. If any interior point lands on a room's fine cell (collision), try the alternate bend orientation; if both collide, set `distorted = true` and emit a direct 2-point segment anyway (honest "doesn't fit"). Carry through `conn.distorted` into `RoutedEdge.distorted` (distorted if either the layout flagged it OR routing couldn't avoid a room).
    - reciprocal-opposite pairs (A→d→B and B→opposite(d)→A) may be deduped to a single `RoutedEdge` (keep the lower-origin-id one, mark it bidirectional via... keep it simple: still emit both but that's fine for v1 — OR dedupe; for v1 emit both, document that the TUI may overdraw identically. Prefer dedupe: skip emitting B→opp→A when A→d→B already emitted between the same pair with opposite dirs).
  - `pub fn fine_cell(pos: (i32,i32)) -> (i32,i32)` = `(2*pos.0, 2*pos.1)`.
