# v6 Phase 0 — Boot & Text-Playable — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a real Version-6 Z-machine story (Zork Zero) load, boot through its `main` routine, and take text turns in zvm without desync or abort — graphics/windows deferred to later phases.

**Architecture:** Native v6 in zvm (no Glk). Four small plumbing changes — header admission, v6 packed-address arm, boot-as-main-routine-call, and correct decode signatures + no-op bodies for the 18 v6 EXT opcodes. The disassembler is already v6-ready and shares the decoder, so the signature fix covers it too.

**Tech Stack:** Rust, zero-dependency `zvm` crate. Tests are std `#[test]` + `#[cfg(test)]` modules.

**Spec:** `docs/superpowers/specs/2026-07-21-v6-phase0-boot-design.md`

## Global Constraints

- **`zvm` stays zero-dependency.** No new entries in `crates/zvm/Cargo.toml` `[dependencies]` (it must remain empty). All work is in `crates/zvm/` except the read-only smoke test's story-file path.
- **No app/render changes.** `startup.rs` already routes accepted Z-machine versions through `GameSession`; v6 flows through unchanged. Do NOT modify the window model / rendering (that is Phase 1).
- **Keep `ZError::GraphicalV6`.** The variant stays (it is `pub`, so no dead-code warning). Do NOT remove it or its two user-facing match arms in `crates/app/src/startup.rs:278` and `crates/zvm-cli/src/main.rs:280`; those arms become unreachable once v6 boots but remain valid and compile. Flag them in the final report for a later cleanup, do not touch them.
- **EXT signatures verified against the Z-Machine Standards Document 1.1, not memory** (§14–§15 opcode tables). See Task 4 Step 1 — this is a hard gate; the table in this plan is the starting point, the ZMSD is the authority.
- Pre-release: no back-compat concerns.
- Match existing code style (surgical edits, existing comment density).

### Task 3: Boot — call `main`, quit when it returns

**Files:**
- Modify: `crates/zvm/src/cpu/exec.rs` `with_output` (~:222-250) and `step()` (~:319-351)

**Interfaces:**
- Consumes: v6 parsing (Task 1), v6 unpack (Task 2), existing `call_routine` (state.rs) and `read_word`.
- Produces: a v6 `Machine` boots with `main`'s frame already on the stack; returning from `main` yields `StepResult::Quit`. Later exec tests (Task 5) can rely on a v6 machine having a base frame.

**Design:** In v6, header word 0x06 is the *packed address of `main`*, called with no args/result (ZMSD §5.5). Reuse `call_routine` to push its frame. v6 is the only version that runs with a base frame, so when the frame stack empties (main returned), `step()` quits. v3–8 run frameless and end via `@quit`, so the check never fires for them.
