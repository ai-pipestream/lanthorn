# zvm — Z-machine Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A headless Z-machine interpreter that loads and correctly executes text-mode story files (v3/v4/v5/v7/v8) to completion via plain stdin/stdout, with Quetzal save/restore and a read-only object-tree/location API for the automapper.

**Architecture:** A single Rust library crate `zvm` plus a thin `zvm-cli` binary that drives it as a "dumb terminal." The library is layered: memory → text codec → objects/dictionary → decoder → executor → I/O/screen → save/restore → mapper-facing API. Each layer is testable in isolation. Correctness is anchored to the **Z-Machine Standards Document v1.1** (hereafter **ZMSD §x.y**) for semantics and to the **CZECH** and **Praxix** regression story files as the objective pass/fail oracle.

**Tech Stack:** Rust (stable, edition 2021), Cargo workspace. No non-std runtime dependencies in `zvm` itself for v1 (pure-std interpreter); the CLI uses only std. Test fixtures are real `.z5` story files downloaded into `tests/fixtures/`.

## Global Constraints

- **Supported versions:** Z-machine **3, 4, 5, 7, 8** only. Reject **1, 2, 6**, and non-Z files at load with a clear error; v6 gets a specific "v6 graphical games are not supported" message. (spec §1, §2, §8)
- **Authoritative semantics:** the Z-Machine Standards Document v1.1. Every opcode/behavior task cites the relevant **ZMSD §**. When this plan and ZMSD disagree, ZMSD wins — fix the plan.
- **Correctness oracle:** the interpreter must pass **CZECH** (`czech.z5`) and **Praxix** (`praxix.z5`) with zero failed subtests. These are the final acceptance gate (Task 16).
- **No filesystem in `zvm`:** the library never reads/writes files for game state. `save()`/`restore()` operate on `Vec<u8>` / `&[u8]`. File I/O belongs to a later `app` plan. (spec §2, §5)
- **Endianness:** all multi-byte values in story memory are **big-endian**. (ZMSD §2)
- **Word = unsigned 16-bit (`u16`).** Signed interpretation is two's-complement `i16` where ZMSD calls for signed arithmetic/branches. (ZMSD §2.1–2.2)
- **TDD:** every task writes a failing test first, then minimal code to pass. Commit after each green task.

## Test Fixtures (one-time setup, part of Task 1)

Download these public regression/story files into `crates/zvm/tests/fixtures/` (they are freely distributed from the IF Archive). They are NOT committed (binary); a `fixtures/README.md` records their source URLs and expected SHA-256 so CI/agents can re-fetch:

- `czech.z5` — Comprehensive Z-machine Emulation CHecker (the primary opcode oracle).
- `praxix.z5` — arithmetic/edge-case checker.
- `minizork.z3` — a small real v3 game (smoke test for real-world play + object tree). Use the freely distributed MiniZork sampler.

If a fixture is missing, the tests that need it must **skip with a clear message** (not silently pass and not hard-fail the unit suite). A helper `fixtures::load(name) -> Option<Vec<u8>>` returns `None` when absent.
