# The room dock: one panel, docked, following

**Status: settled 2026-08-06 (all three open questions answered by Marcus)**

## What exists today

Two panels describe a room, both floating corner dialogs over the map:

- **Room info** (left-click a room): name, notes, the per-direction **exit
  card** in the matrix vocabulary, and — for the current room — objects read
  live from the engine.
- **Inspector** (right-click, or `/toggle-inspector`): layout diagnostics —
  id, layer, grid position, edges with distortion flags, discovery method.

They already share one state struct (`RoomPanel { id, mode }`), but each is a
popup pinned to the room you clicked: it obscures the map it describes, counts
as a modal overlay (`any_overlay_open`), never follows the player, and closes
on Esc/✕/pane-switch.

## The proposal

Replace both with **one dock that slides in at the bottom of the map pane** —
the third `PanelSlide` dock, after the inventory dock and the command band.

- **Toggle, not popup.** Opened and closed deliberately; stays up while you
  play. Not a modal overlay: the map above it stays fully interactive, and no
  Esc ladder is spent on it.
- **Follows by default.** With nothing selected, the dock describes the room
  the player is standing in, updating every move — a live "where am I, what
  have I tried" readout, which is what the exit card was always for.
- **Click to pin.** Clicking a room selects it (as today) and points the dock
  at it. The header says which regime it is in — `⌖ following` vs `📌 pinned`
  (final glyphs TBD; styleable either way).
- **Unpin** returns to following. (Gesture: open question below.)
- **Drag-resizable** at its top edge like every pane boundary (SQ-0672
  machinery, a new `ResizeTarget::RoomDock`), height persisted like
  `inv_dock_pct`.
- **Styleable** end to end: `room_dock`, `room_dock.header`,
  `room_dock.header:pinned`, plus the exit-card styles it inherits.
- **Matrix layers**: the dock coexists with the matrix view — selection is
  already shared (`selected_room` drives both the matrix cross-highlight and
  the dock), so arrowing the matrix and reading the dock is one gesture.

## Content

The Info body is the base: room name + layer, notes, the exit card, objects
(live, current room only — the engine cannot introspect a room the player is
not in beyond the map's own record). Diagnostics (grid pos, distorted edges,
discovery method) folds in — how is an open question below.

Wide docks can spend columns instead of rows: name/notes/objects left, exit
card right — the card is a fixed twelve lines that sets the natural minimum
height; a shorter dock scrolls.

## Decisions (settled)

1. **Diagnostics are a second dock view.** Info is the default body;
   `/toggle-inspector` (and a key inside the map context) flips the SAME dock
   to the diagnostics body for the same room. One dock, two views.
2. **Unpin is generous — all three gestures work.** A click on empty map
   space, a click on the already-pinned room, and Esc each return the dock to
   following. Esc's ladder: unpin first, close the dock on the next press.
3. **The popups retire entirely.** With the dock closed, any left-click on a
   room opens the dock pinned to it; right-click opens it pinned in the
   diagnostics view. The floating dialogs are gone.

**Pin state IS the room selection.** `selected_room: Some(id)` = pinned to
`id`; `None` = following `graph.current()`. No second piece of state to
drift: the map highlight, the matrix cross-highlight, and the dock header all
read the same fact. (Side effect accepted: anything that selects a room —
e.g. a layer switch landing on a room — pins the open dock; the header shows
it and any unpin gesture clears it.)

## Retirements

- `draw_room_info` / `draw_inspector` as floating dialogs, `RoomPanel`
  overlay-state, and their `any_overlay_open` participation.
- `ShowRoomInfo` / `ShowRoomDiagnostics` / `CloseRoomPanel` actions collapse
  into dock actions.
- `/toggle-inspector` renamed or absorbed (old spelling kept as an alias).
