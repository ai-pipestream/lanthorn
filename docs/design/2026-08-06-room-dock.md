# The room dock: one panel, docked, following

**Status: settled 2026-08-06 (all three open questions answered by Marcus)**

## What exists today

Two panels describe a room, both floating corner dialogs over the map:

- **Room info** (left-click a room): name, notes, the per-direction **exit
  card** in the matrix vocabulary, and — for the current room — objects read
  live from the engine.
- **Inspector** (right-click, or `/toggle-inspector`): layout diagnostics —
  id, layer, grid position, edges with distortion flags, discovery method.

They already share one state struct (`RoomPanel { id, mode }`), but each is a
popup pinned to the room you clicked: it obscures the map it describes, counts
as a modal overlay (`any_overlay_open`), never follows the player, and closes
on Esc/✕/pane-switch.

## The proposal

Replace both with **one dock that slides in at the bottom of the map pane** —
the third `PanelSlide` dock, after the inventory dock and the command band.

- **Toggle, not popup.** Opened and closed deliberately; stays up while you
  play. Not a modal overlay: the map above it stays fully interactive, and no
  Esc ladder is spent on it.
- **Follows by default.** With nothing selected, the dock describes the room
  the player is standing in, updating every move — a live "where am I, what
  have I tried" readout, which is what the exit card was always for.
- **Click to pin.** Clicking a room selects it (as today) and points the dock
  at it. The header says which regime it is in — `⌖ following` vs `📌 pinned`
  (final glyphs TBD; styleable either way).
- **Unpin** returns to following. (Gesture: open question below.)
- **Drag-resizable** at its top edge like every pane boundary (SQ-0672
  machinery, a new `ResizeTarget::RoomDock`), height persisted like
  `inv_dock_pct`.
- **Styleable** end to end: `room_dock`, `room_dock.header`,
  `room_dock.header:pinned`, plus the exit-card styles it inherits.
- **Matrix layers**: the dock coexists with the matrix view — selection is
  already shared (`selected_room` drives both the matrix cross-highlight and
  the dock), so arrowing the matrix and reading the dock is one gesture.

## Content

The Info body is the base: room name + layer, notes, the exit card, objects
(live, current room only — the engine cannot introspect a room the player is
not in beyond the map's own record). Diagnostics (grid pos, distorted edges,
discovery method) folds in — how is an open question below.

Wide docks can spend columns instead of rows: name/notes/objects left, exit
card right — the card is a fixed twelve lines that sets the natural minimum
height; a shorter dock scrolls.

## Decisions (settled)

1. **Diagnostics are a second dock view.** Info is the default body;
   `/toggle-inspector` (and a key inside the map context) flips the SAME dock
   to the diagnostics body for the same room. One dock, two views.
2. **Unpin is generous — all three gestures work.** A click on empty map
   space, a click on the already-pinned room, and Esc each return the dock to
   following. Esc's ladder: unpin first, close the dock on the next press.
3. **The popups retire entirely.** With the dock closed, any left-click on a
   room opens the dock pinned to it; right-click opens it pinned in the
   diagnostics view. The floating dialogs are gone.

**Pin state IS the room selection.** `selected_room: Some(id)` = pinned to
`id`; `None` = following `graph.current()`. No second piece of state to
drift: the map highlight, the matrix cross-highlight, and the dock header all
read the same fact. (Side effect accepted: anything that selects a room —
e.g. a layer switch landing on a room — pins the open dock; the header shows
it and any unpin gesture clears it.)

## Retirements

- `draw_room_info` / `draw_inspector` as floating dialogs, `RoomPanel`
  overlay-state, and their `any_overlay_open` participation.
- `ShowRoomInfo` / `ShowRoomDiagnostics` / `CloseRoomPanel` actions collapse
  into dock actions.
- `/toggle-inspector` renamed or absorbed (old spelling kept as an alias).

## Amendment, 2026-08-06 (implementation, SQ-0692)

Two details settled during implementation, neither changing a decision above:

- **Pin glyph.** The sketch's `📌` is an emoji, and emoji are double-width in a
  terminal cell grid — the header is drawn cell by cell like every other line in
  the dock, so a double-width glyph would shear the rest of the line. Shipped as
  `⌖ following` / `⊙ pinned`, both BMP and single-width.
- **`/toggle-inspector` no longer requires a selection.** The old command was a
  no-op with no room selected, which meant the reading you usually want — of the
  room you are standing in — was the one it could never give you. It now opens
  the dock on the diagnostics body for whatever room the dock is showing, and
  flips Info ↔ Diagnostics when the dock is already up. `toggle-room-dock` is
  the primary open/close toggle (leader `k`), opening on Info.
- **Where the rows come from.** The dock is carved out of the MAP pane's bottom,
  not the frame's, so the story pane is untouched and the dock lands inside the
  pane it describes. Its height is still a percentage of the FRAME
  (`room_dock_pct`, default 40) so `dock_pct_for_rows` inverts it exactly as it
  does the inventory dock's; the map pane's own floor (three rows) is what caps a
  greedy percentage, since a percentage cannot know how tall the pane is.
- **Info body order, and the default height.** The Info body draws notes →
  `Here:` → the exit card, not the card first. A real-game smoke test found the
  objects section unreachable at the shipped dock height: the card is a fixed
  thirteen-line block, so anything under it needs a dock taller than a 40-row
  terminal can spare. The card is the section that runs off the bottom now,
  which it survives — every one of its rows is the same shape, so the ones that
  fit still read. `room_dock_pct` defaults to **40**, not the inventory dock's
  33, because the Info body's natural height is ~16 rows and 33% of a 40-row
  terminal is 13. The "wide docks spend columns instead of rows" sketch above
  is NOT implemented; it is still the right answer for very wide terminals.
  *(Superseded 2026-08-07 — see below: the sketch is implemented, and the
  default is back to 33.)*

## Amendment, 2026-08-07 (SQ-0694)

Marcus reviewed the shipped dock and asked for two refinements. Both are in.

- **The columns sketch is implemented.** "Wide docks can spend columns instead
  of rows" is no longer a sketch: the exit card lays its lines out in a grid,
  filled COLUMN-MAJOR, with the column count derived from the available width
  against the widest line — measured in display CELLS (`textwidth::str_cells`),
  never a char count, since a full-width destination name occupies two columns
  per glyph. Fewest rows wins (the `ls` rule). The grid is capped at **three**
  columns, which is a meaning limit rather than a width one: `MATRIX_DIRS` is
  three groups of four, so three column-major columns put the cardinals, the
  diagonals and the portals each in their own column. Letting the width alone
  decide gives six columns of two on a wide pane — more compact, and it shatters
  the groups. Graceful degradation is unchanged: a dock too short for every card
  row draws the rows that fit, in full, and a card wider than the dock falls back
  to one clipped column.
- **Consequently `room_dock_pct` is back to 33**, the inventory dock's default.
  The natural Info body is now header + `Here:` + objects + `Exits:` + four card
  rows ≈ nine to eleven rows, not sixteen; 33% of a 40-row terminal is thirteen,
  which admits the whole body with room to spare. `tests/room_dock_render.rs`
  pins that at the shipped default rather than restating the arithmetic.
- **The view tabs are the shared strip.** They always were — `draw_panel` +
  `PanelStrip` with `panel.tab` / `panel.tab:active`, the same component and the
  same selectors as the map pane's layer tabs and the debug pane's section tabs
  — so there was nothing to migrate. What was missing was proof and polish: the
  click routing moved out of the run loop into `input::room_dock_mouse_action`
  so a test can synthesize a click on every cell of every returned tab rect and
  assert the body flips, and the dock now draws its frame in the MAP pane's
  glyphs rather than the default set, so the two stacked panes are drawn in one
  hand.
