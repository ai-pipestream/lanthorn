## MAP Enhancements

1. [ ] Same-name room disambiguation (connectivity-based identity). Today a room's identity is `synthetic_room_id(name)` (FNV hash of the name), so two genuinely different rooms sharing a name collapse into one graph node and a walk between them registers as no move (`mapper.observe`: `location == prev_id`). This also affects the Z-machine `NameOnly` path, not just Glulx — it's engine-agnostic. FIX DIRECTION: identify a room by its position in the movement graph rather than its name — when the player moves `via` a direction from a known room, a target that isn't the expected existing neighbour becomes a NEW node even if the name collides; the name degrades to a label + consistency check. Needs a reliable "did we actually move?" signal (blocked exits must not mint nodes) and user split/merge to correct mistakes (IF maps are frequently non-Euclidean: mazes, one-way passages, N-then-S not returning). Overlaps the deferred fundamental mapping/layout redesign research. Alternative for EXACT identity: read Inform's object tree / `location` global from Glulx memory (Glulx analogue of Z-machine PlayerParent) — research-heavy, version-fragile, no standard pointer to globals/objects. Prereq/relation: builds on the Glulx room-detection spec (docs/superpowers/specs/2026-07-02-glulx-room-detection-design.md §7). [automapping; mapper identity model — mapper.rs observe/upsert_room + graph node identity]
1. [ ] Vertical-exit placement + routing convention. UP exits: place the destination room to the NORTHWEST of the origin, and route the up dotted portal path out of the UPPER LEFT of the room. DOWN exits: place the destination room to the SOUTHEAST. (Gives up/down a consistent diagonal layout direction and a predictable portal-path.) [automapping; mapper layout placement for up/down portals + render/map.rs portal-connector side]
